# CHANGELOG

发布说明按大版本分树（`v0/`、`v1/`……），每个版本一个目录，目录内固定为一份 `CHANGELOG.md`。

- 目录名必须与 Git 标签完全一致（标签 `v0.1.0` ↔ 目录 `CHANGELOG/v0/v0.1.0/`）。
  大版本归属以本目录的树为准，而不是标签号：`v0.x` 进 `v0/`，`v1.x` 进 `v1/`。
- 文件内容会被 `.github/workflows/Publish.yml` 的 `scripts/gen-release-note.ps1` **直接用作
  GitHub Release 正文的开头**，脚本只按 `CHANGELOG/**/<tag>/CHANGELOG.md` 找（不猜层级），
  所以目录名写错就等于这次发布没有说明（会回退成「发布说明待补充」）。
- 下载表与 SHA256 表由脚本自动追加，**不要**在 `CHANGELOG.md` 里手写这两张表。
- 只写用户需要看的内容；开发过程、内部重构细节不进这里。

## 正式版 note 模板

正式版（无预发布后缀）用下面这段开头，只替换版本号，其余文字保持一致：

```markdown
> [!note]
>
> # vX.Y.Z 正式版发布
>
> 感谢您一路以来的等待与支持，**vX.Y.Z 正式版**现已发布，可直接用于日常使用。
>
> **📣 我们需要您**：如果发现任何 Bug，或有功能改进建议，欢迎随时前往 **GitHub Issues** 提交反馈。
>
> 感谢您陪伴 Corkboard 一路走到这里！
```

## Beta note 模板

Beta 版本用 `> [!caution]` 提示风险：

```markdown
> [!caution]
>
> # 抢先体验 Beta 版
>
> 您正在使用我们的最新功能预览版。为了在正式版中给您带来更完美的体验，我们需要您的帮助与反馈。
>
> **⚠️ 风险提示**：此版本尚在打磨中，可能存在偶发异常或未知问题，**请务必避免用于关键业务或生产环境**。
>
> **📣 我们需要您**：如果发现任何 Bug，或有功能改进建议，欢迎随时前往 **GitHub Issues** 提交反馈。
>
> 感谢您成为我们的首批体验官！
```

## Alpha note 模板

Alpha 用 `> [!caution]` 明确提示不要在生产环境使用：

```markdown
> [!caution]
>
> # 警告！当前版本为 Alpha 版本，请勿在生产环境使用
>
> **⚠️ 警告**：当前版本为 **Alpha 版本**，**请勿在生产环境使用**。当前版本可能存在未知 Bug，仅供用户体验。使用中如遇问题，欢迎前往 **GitHub Issues** 反馈！
```

正文其余部分沿用固定结构：`# <版本号> - <代号>` 标题、`## 🚀 主要更新` / `## 💡 功能优化` /
`## 🐛 修复问题` 三个板块（**没有内容的板块整节省略，不用「无」占位**——首版通常只有「主要更新」，
确实需要占位时才写「无」），需要时补 `## 🙏 贡献者`，结尾固定为 `---` 加
「💝 **感谢所有贡献者为 Corkboard 项目付出的努力！**」。
